# コトツナ

🔗 **公開URL**: https://asahi-news-context.vercel.app
📦 **リポジトリ**: https://github.com/katsuki22017/asahi-news-context

日常で感じた小さな「あれ？」を、社会や政治とのつながりに変えるチャット型Webサービスです。

朝日新聞社の1dayイベントで行われたアイデアソン「高校生の社会問題への関心を高めるWebサービスを、朝日のアセットを利用して考える」に参加した際に生まれたアイデアを、個人開発として実装しました。アイデアソン当日はチームで「それ政治です」という名前で発表しましたが、個人開発で実装するにあたり「コトツナ」と改名しています。

## 背景・課題意識

高校生は「コンビニのおにぎりが値上がりした」「奨学金の話をよく聞く」といった身近な出来事は経験していても、それが物価政策や教育政策といった社会・政治の問題とつながっていることに気づきにくい、という仮説からスタートしました。断片的な出来事の記憶だけでは、ニュースを「自分ごと」として捉えることが難しく、将来の選挙参加などにもつながりにくいと考えました。

## 解決アプローチ

チャット形式で身近な出来事を入力すると、次の3つを提示します。

1. 身近な出来事と社会・政治の問題をつなぐ因果関係の説明
2. その経緯を段階ごとに整理した年表(なぜ今そうなっているのか、流れが一目でわかります)
3. 説明の根拠にした、関連する朝日新聞デジタルの記事(タイトル・要約・実際のURL)

記事に書かれている事実と、AIが持つ一般的な社会科の知識(教科書のような、広く知られている仕組みの説明)を組み合わせて説明を作っています。実在する教科書データを参照しているわけではなく、あくまでAIモデル自体が持つ一般知識です。その際、「記事に基づく事実」なのか「一般的に知られている知識」なのかを読者が区別できるよう、AIへの指示(プロンプト)で書き分けています。詳しい設計判断は下の「工夫した点・設計判断」をご覧ください。

## 機能

- チャット形式のシンプルなUI
- 入力文からのキーワードマッチングによる関連記事の一次絞り込み(サーバーサイド、AIを使わないスコアリング)
- Claude APIによる年表・因果関係・自分ごと化の説明文生成
- レート制限・入力文字数制限などの基本的な安全対策
- スマホでの表示を想定したレイアウト・ダークモード対応

## 技術スタック

- Next.js (App Router) / TypeScript
- Tailwind CSS
- Anthropic Claude API (`@anthropic-ai/sdk`)
- Vercel(デプロイ)

## 工夫した点・設計判断

開発を通じて特に悩んだ・工夫したポイントをまとめます。

### 1. 記事マッチングのスコアリング設計

入力文と記事のキーワードを照らし合わせ、関連度の高い記事を選ぶ仕組みです。AIを使わず軽い処理で一次選別することで、コストを抑えつつ精度を保つよう工夫しました。

当初は「タイトルの単語が2文字でも入力に含まれていれば+1点、1点でもあれば採用」という荒い基準でしたが、これだと助詞のような一般的すぎる短い単語で無関係な記事が紛れ込みやすく、タイトルが長い記事ほど有利になってしまう問題がありました。そこで、タイトルの単語一致は3文字以上に限定して加点の上限も設け、事前に手動登録したキーワード・トピック名との一致を主な判断材料とし、そのどちらかに当てはまった記事だけを採用するよう調整しました。記事やキーワードを増やしていく際にスコアの内訳を確認できるデバッグ用の仕組みも用意しています。

### 2. 年表の再定義:「日付の記録」から「因果関係の分解」へ

理想としては、身近な出来事の背景にある社会の動きを「いつ、何が起きて今に至るのか」という正確な時系列として見せたいと考えていました。しかし、時系列として成立させるには、複数の出来事とその日付を検証済みの情報源から積み上げる必要があります。限られた情報だけでそれを組み立てようとすると、実際には確認できていない出来事や日付をそれらしく補ってしまう(ハルシネーションしてしまう)リスクが常につきまといます。これはニュースを扱うサービスとして、最も避けたいことでした。

そこで、年表を「いつ、何が起きたか」の記録としてではなく、「①の因果関係の説明文を、2〜4ステップの箇条書きに整理し直したもの」として再定義しました。各ステップの日付は、参考記事に明記されている場合のみ使用し、明記されていない段階は「背景」「現在」「今後」のような大まかな時期ラベルにすることで、架空の日付を作らずに済むようにしています。

### 3. ハルシネーション対策と一般知識の使い分け

ニュースを扱うサービスとして、AIが記事にない情報をそれらしく作り出してしまう(ハルシネーション)ことを最も警戒しました。当初は「参考記事に書かれている情報だけを事実の根拠とする」という厳格なルールにしていましたが、それだと記事1本の情報だけでは因果関係を十分に説明しきれない場面が多くありました。

そこで、実在しそうな具体的な統計・日付・固有名詞の捏造は禁止しつつ、記事の内容につながる一般的な社会・政治・経済の仕組み(AIが持つ、教科書のような一般知識。実在の教科書データそのものを参照しているわけではありません)は積極的に使ってよいこととし、「記事に書かれている事実」と「一般的に知られている知識」を読者が区別できるよう、後者には「一般的には〜と言われています」のようなヘッジ表現を使うようプロンプトで指示しています。本来は実在するデジタル教科書のような、検証可能な情報源を参照できるのが理想だと考えていますが、今回は時間の制約でAIの一般知識を使う形にとどめています。

### 4. スマホ表示で見つかったバグ

実装後、実際にモバイル幅で動作確認したところ2つの問題を発見しました。

- AIの回答が届くと自動的に一番下(参考記事欄)までスクロールしていたため、スマホなど画面が狭い場合に肝心の説明文が画面外に隠れてしまっていた → 回答の先頭が見える位置までスクロールするよう修正
- Next.jsの初期テンプレート由来のダークモード対応CSSが残っており、端末がダークモード設定だと白背景のカードの上で文字色だけが白っぽくなり、ほぼ読めなくなっていた → アプリ全体をライトテーマに固定して解消

## セットアップ(ローカル開発)

```bash
npm install
cp .env.local.example .env.local
# .env.local を開いて ANTHROPIC_API_KEY を実際の値に書き換える
npm run dev
```

http://localhost:3000 で確認できます。

## 現在の記事データについて

`src/data/articles.json` には、実際に朝日新聞デジタルで公開されている記事(見出し・URL・自分の言葉での要約)を手作業で収集して登録しています。著作権・利用規約への配慮から、記事本文はスクレイピング・保存せず、見出し・URL・自分の言葉での短い要約のみを保持しています。

現時点では「物価高」「若者と政治」「教育費」の3テーマ・3記事のみのプロトタイプ段階です。記事を増やすほど対応できる話題やマッチング精度が上がるため、今後の主な拡張ポイントだと考えています。

なお、朝日新聞デジタルの利用規約にあるAI関連のデータ収集条項は認識した上で、企業への説明・評価目的の少量(3記事)プロトタイプとして公開しています。

## セキュリティ上の配慮

- Claude APIキーはサーバーサイド(API Route)でのみ使用し、環境変数から読み込みます。クライアントに露出しません。
- 記事本文はスクレイピング・保存していません(詳細は上記「現在の記事データについて」を参照)。
- AIへのプロンプトで「記事にない具体的な事実(統計・日付・固有名詞など)を捏造しない」ことを明示的に指示し、実在しない出典が事実であるかのように出力されるリスクを抑えています。
- IPアドレスベースの簡易レート制限、入力文字数の上限(200文字)を設けています。
- チャット履歴はサーバーに保存していません(セッション内のみ)。

## 現状の限界点

正直に書いておくと、以下は現時点でまだ対応できていません。

- 記事データが3件のみで、実運用には全く足りていない(手作業収集のコストが主なボトルネック)
- レート制限がインメモリ実装のため、Vercelのようなサーバーレス環境では厳密には機能しない場合がある(本格運用時はUpstash Redis等の外部ストアが必要)
- 自動テスト(ユニットテスト・E2Eテスト)を整備できていない。動作確認は手動 + 一時的なデバッグ用ルートでのスコア検証が中心
